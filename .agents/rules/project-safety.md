# 「暗号快传」项目安全与体验红线规则

在修改或扩展本项目任何代码时，必须严格遵守以下底线：

1. **防 XSS 注入**：所有用户输入、对方发来的文件名与文字消息，必须使用 `textContent` 或安全转义方式渲染，严禁拼接进 `innerHTML`。
2. **严格 1 对 1 锁房**：发送方已建立活跃连接时，必须自动拒绝第 3 个及以上的连接并提示“房间已满”，不得中断当前传输。
3. **双重确认机制**：
   - 发件方收到连接请求时必须手动同意连接。
   - 收件方看到纯文本文件名与大小后，必须手动点击“接收”才开始传输，严禁静默自动下载。
4. **暗号防撞与规范**：
   - 系统默认生成 6 位防混淆随机暗号（排除 `0/O/1/I/l`）。
   - 用户自定义暗号长度不得少于 4 位。
   - 随机暗号撞车时自动重摇；自定义暗号被占用时友好提示更换。
5. **大文件稳定性与完整性**：
   - 必须使用 WebRTC 可靠有序通道（`ordered: true`）。
   - 发送端使用 64 KB 分片 + `bufferedAmount` 缓冲区背压流控。
   - 接收端必须校验最终收到的总字节数与原文件大小完全一致才触发下载，并在完成后立即释放内存。
   - 文件超过 500 MB 时给出大文件友好提示。
6. **防误关与断线清理**：
   - 传输进行中拦截页面关闭/刷新。
   - 断线或超时（15 秒）立即清理临时状态与内存，给出清晰中文提示。
   - 连接建立后若连续 5 分钟无任何文件或文字传输（空闲超时），自动断开连接并提示，避免接收方无限干等及长期占用房间。
7. **开源透明声明**：页面底部与 `README.md` 必须保留“点对点直连、不存服务器、需双方同时在线、P2P 对通信方可见 IP（建议熟人/自用）”的清晰说明。
